# 2026-08-30 — R54: Progent symbolic-rule import PoC

**Item.** R54 (first unchecked item, done whole in one run per the
2026-08-25 cadence rule): translate a subset of Progent's symbolic
policy rules into APG policies — converter + fidelity tests + a worked
example.

**Ground truth.** The imported format is pinned to Progent's actual
runtime representation (verified today against
`sunblaze-ucb/progent@main`, `secagent/tool.py`):
`{tool_name: [(priority, effect 0=allow/1=forbid, {arg: restriction},
fallback 0=error-msg/1=terminate/2=user-confirm)]}`, rules sorted by
`(priority, -effect)` (forbid before allow at equal priority), walked
in order; a restriction is a JSON Schema dict, a bare regex string
(`re.match` semantics), or a callable; a tool with no entry — and a
call that falls off the end of its rule list — is denied.

## Plan

- `policy.py`: new `Selector.arg_matches` — per-argument regex
  (compile-validated, `re.search` semantics like JSON Schema `pattern`,
  non-string values never match). Progent's flagship rules are
  pattern-shaped; without regex args the translatable subset is toothless.
- New `progent_import.py`: `ProgentRule` model, `load_progent_policy` /
  `load_progent_policy_str` (JSON), `convert_progent_policy` → APG
  `Policy` (Progent sort order → first-match order; effect/fallback
  mapping allow / deny / review; enum expansion; trailing default-deny),
  `policy_to_yaml` serializer that round-trips through `load_policy_str`.
  Unsupported constructs (callables, 5-tuple self-updating policies,
  JSON Schema keywords outside the subset) fail the import loudly —
  never silently weaker.
- `cli.py`: `apg policy import-progent FILE [--name] [--default
  {deny,per-tool}] [-o FILE]`; explain trace + lint W001/W002 taught
  about `arg_matches` (conservative, like chain conditions).
- `examples/progent/`: banking-style Progent JSON + `__main__` demo
  (convert, print, gate three calls) that doubles as a CI sanity check.
- Tests `tests/test_progent_import.py` incl. a reference evaluator
  ported from Progent's `_check_tool_call` for decision-fidelity checks;
  `test_policy.py` additions for `arg_matches`.
- Docs: `docs/design.md` R54 section (incl. the documented divergences),
  `docs/cli.md`, CHANGELOG, ROADMAP move, this log.

## What shipped

Everything planned, in one run. Decisions worth recording (all in
`docs/design.md` "Progent rule import (R54)"):

1. **The imported format is upstream's, not the paper's.** The rule
   tuple, the `(priority, -effect)` sort, the `re.match` bare-string
   shorthand, the hard-allow (priority 100 + fallback 0) and the
   leaky-fallback quirk (fall-off-the-end handled with the *last
   examined rule's* fallback) were all read out of
   `secagent/tool.py` and are carried faithfully — including a
   trailing `review` (not `deny`) for a tool whose last rule says
   "ask the user".
2. **`Selector.arg_matches` is the load-bearing DSL addition.**
   Per-argument regexes with `re.search` semantics (the JSON Schema
   `pattern` convention); presence + string required; explain traces,
   lint W002 (arg_equals-vs-arg_matches contradiction) and a
   conservative W001 all taught about it.
3. **Unsupported means loud.** Callables, self-updating 5-tuples,
   JSON Schema keywords beyond const/enum/pattern/type:string, float
   and null scalars raise `ProgentImportError` — the translation is
   never silently weaker. Within the subset, decisions are pinned
   against a reference evaluator ported from upstream
   `_check_tool_call` over a policies × calls battery; the three
   divergences (absent args fail closed, non-strings never satisfy
   `pattern`, terminate → deny) each have an explicit test.
4. **`policy_to_yaml` makes the output a reviewable artifact.**
   Generic serializer, round trip pinned for generated and shipped
   policies alike; `apg policy import-progent` wires it to the CLI
   (exit 0 / 1 outside-subset / 2 missing-or-unwritable), and
   `examples/progent/` runs Progent JSON → YAML → gateway decisions
   as a CI sanity check.
