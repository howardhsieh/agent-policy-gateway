# 2026-09-01 — R56: APG / Progent / Fides comparison measurement

**Item.** R56 (first unchecked item, done whole in one run per the
2026-08-25 cadence rule): run the three policy paradigms — APG's stateful
policies, Progent-style stateless symbolic rules, and Fides-style

scenario family and publish the comparison, including the selective
chain policy the R55 write-up called for (recover the chain arm's
utility loss without reopening the overt attack).

## Plan

- `comparison_benchmark.py`: an R55-style deterministic benchmark whose
  scenario family adds the observables the comparison needs — sink calls
  carry a `recipient` argument (trusted / attacker-controlled / novel),
  a confidential `read_secret` source joins the untrusted reader, and
  the armed family splits into overt (attacker-recipient), covert
  (trusted-recipient) and exfiltration variants; benign adds clean,
  novel-recipient, post-read direct/laundered, and secret-touching
  flows. Six arms over the same 90 scenarios: no-defense, progent
  (`policies/comparison-progent.json` converted at run time through the
  real R54 importer), fides (`policies/comparison-fides.yaml`, R51
  dual-label: integrity rules + confidentiality rules + integrity-only
  endorse grant), apg-input-taint / apg-chain (the shipped R55
  policies, unchanged), and apg-chain-selective
  (`policies/comparison-chain-selective.yaml`: allow trusted
  recipients first, then chain-deny after an untrusted read).
- Per-arm summary: utility over benign scenarios, compromise overall and
  per attack variant; text table + `--json`; `main` / `__main__`.
- Worked example `examples/comparison/` asserting the headline
  invariants (CI check); write-up `docs/benchmarks/comparison.md`;
  design.md R56 section; CHANGELOG; ROADMAP move; tests pinning the
  full per-arm matrix (`tests/test_comparison_benchmark.py`, plus the
  policies-directory pin update in `test_policy.py`).

## What shipped

Everything planned, in one run — R56 whole, closing the 2026-08-21 plan
revision's three phases (R49–R56 all done). Decisions worth recording
(all in `docs/design.md` "APG / Progent / Fides comparison measurement
(R56)"):

1. **The family gains exactly the observables the paradigms need to
   come apart.** Sink calls carry a `recipient` argument (trusted
   namespace / legitimate-but-novel / attacker-controlled) so a
   symbolic rule has something to match; a confidentiality-only
   `read_secret` source joins the untrusted reader so a dual-label
   policy has something only it can stop. Ten variants × 3 sinks ×
   horizons 1–3 = 90 scenarios through the unchanged R55 harness;
   every arm shares runtime, gateway wiring and taint specs, so the
   arms differ in nothing but their policy.
2. **The Progent arm goes through the real R54 pipeline** — a
   Progent-format JSON converted at run time by
   `load_progent_policy`/`convert_progent_policy`, so the benchmark
   doubles as an end-to-end importer exercise. **The Fides arm is an
   explicit session-granular approximation** (R51 integrity +
   confidentiality rules, integrity-only endorse grant), with the
   granularity caveat stated in the write-up.
3. **`apg-chain-selective` is the constructive result** the R55
   write-up called for: `arg_matches` trusted-recipient allow
   first-match, then the R53 chain deny. It recovers *all* the chain
   arm's lost utility (100% vs 60%, novel recipient included) at the
   imported Progent policy's exact compromise profile — session state
   strictly dominates the equivalent stateless allowlist.
4. **The impossibility is measured, not asserted.** In every arm,
   covert-launder compromise equals benign launder utility: the covert
   attack sink call is the same observable event as the legitimate
   flow, so a call-level policy only chooses where to pay. Only the
   fides arm stops exfiltration (and pays on the benign secret flow).
   No arm dominates; the frontier {chain, chain-selective, fides} is
   the published result.
