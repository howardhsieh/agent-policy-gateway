# 2026-08-05 - R43: negative filters (`--exclude-tool/--exclude-agent/--exclude-rule`)

## Roadmap item

**R43. Negative filters: `--exclude-tool/--exclude-agent/--exclude-rule`.** Repeatable
glob *exclusions* that drop matching records after the include filters run, mirroring
`filter_by_tool/agent/rule` but inverted. A record is dropped when it matches *any*
exclude pattern; includes are applied first, then excludes.

## Plan

- Add a pure `exclude_by(records, key, patterns)` to `audit.py` that resolves `key`
  (`"tool"`/`"agent"`/`"rule"`) to the same value extractor the include filters use --
  `call.tool_name`, `call.agent_id or _NO_AGENT`, `decision.rule_id or _NO_RULE` -- so
  the sentinel buckets are excludable by their literal labels.
- Add three thin wrappers `exclude_by_tool/exclude_by_agent/exclude_by_rule` for
  symmetry with the include helpers; export all four from `audit.__all__` and the
  package root.
- Wire `--exclude-tool/--exclude-agent/--exclude-rule` (repeatable, `action="append"`,
  default `None`) into the `audit stats` parser and apply them in `_cmd_audit_stats`
  *after* `filter_by_tool/agent/rule`, before either renderer.
- Extend `tests/test_audit_stats.py` with a pure-helper class (each axis, sentinels,
  multi-pattern union of exclusions, exclude-nothing passthrough, case sensitivity,
  order preservation, unknown-key error) and a CLI class (each flag, include+exclude
  composition, repeatability, composition with `--json`).
- Roadmap/CHANGELOG bookkeeping; no design-doc change (this is a straight mirror of the
  existing filter axis, no new design decision).

## Notes / decisions

- Implemented `exclude_by` with an axis-keyed extractor table *and* the three wrappers
  rather than picking one of the two options the roadmap allowed: the table keeps the
  fnmatch + sentinel logic in a single place, and the wrappers keep the CLI call site and
  the public API symmetric with `filter_by_*`.
- An unknown `key` raises `ValueError` (mirroring `audit_stats_section_csv`'s unknown
  section) rather than silently passing records through.
- The local test helper was named `_mixed_records`, colliding with an existing
  module-level fixture of that name used by the R40/R30 CSV/dict tests; renamed to
  `_exclude_records`.
- No `docs/design.md` change: this is a straight inversion of an existing filter axis and
  introduces no new design decision.
