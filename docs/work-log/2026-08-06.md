# 2026-08-06 — R44: `apg audit stats --count-only`

## Roadmap item

**R44. `apg audit stats --count-only`.** A scripting-friendly mode that prints
just the filtered record count (one integer line) instead of the full summary,
composing with every filter and with the `--fail-over` gate (count printed, then
the gate decides the exit code). Mutually exclusive with `--json`/`--csv`. Tests
cover the integer output, composition with filters, the fail-over interaction,
and the mutual-exclusion usage error (exit 2).

## Plan (smallest change that satisfies the acceptance criteria)

- Add `--count-only` (`store_true`) to the existing `fmt_group`
  mutually-exclusive group on the `audit stats` subparser, so argparse itself
  rejects `--count-only --json` / `--count-only --csv` with its usual exit 2.
- In `_cmd_audit_stats`, add a `--count-only` branch *after* all include/exclude
  filters have been applied and *before* the CSV/JSON/text renderers: print
  `len(records)` and return `_fail_over_code(...)` so the gate still decides the
  exit code.
- Leave the `--csv-section requires --csv` guard untouched — it already fires
  (exit 2) when `--csv-section` is passed without `--csv`, including alongside
  `--count-only`.
- Extend `tests/test_audit_stats.py` with a `TestAuditStatsCountOnly` class
  covering: bare integer stdout, empty log → `0`, composition with
  `--verdict`/`--tool`/`--exclude-tool`/multi-log, the `--fail-over` interaction
  (count printed, exit 5), and the two mutual-exclusion usage errors.
- Update `ROADMAP.md` (move R44 to Done) and `CHANGELOG.md`.

## Design notes

- **Why the mutually-exclusive group and not a hand-rolled guard.** R42's
  `--csv-section` needed a custom check because it *modifies* `--csv` rather
  than competing with it. `--count-only` is a peer renderer, so putting it in
  the existing `fmt_group` gets the "mutually exclusive with `--json`/`--csv`"
  acceptance criterion — including the exit-2 usage error — from argparse for
  free, with a message consistent with the pre-existing `--csv --json` error.
- **Print-then-gate.** The count goes to stdout *before* `_fail_over_code` runs,
  matching the contract `--csv` and `--json` already have: the artifact is
  always emitted, and the exit code is a separate CI signal. A gated run
  therefore still yields a usable number on stdout.
- **Filter placement.** The branch sits after the include and exclude filters
  and before all three renderers, so `--count-only` reports exactly the
  population every other renderer would have summarized.
