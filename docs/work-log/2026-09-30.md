# 2026-09-30 (evening) — Howard-directed session: integrate APG with TraceSig and agent-security-skills, prepare 0.2.0

Howard asked for the three sibling repositories to be integrated and
released overnight. This entry records what changed in APG and why, in
the order it was done. The morning run above is unchanged.

## What changed and why

1. **R63 — `session_id` and `labels` in the TraceSig export.**
   *What:* two new derived fields on every exported event, a
   `--session-id` flag on `apg audit export`, and a `session_id=`
   keyword on the export functions.
   *Why:* TraceSig's trace schema groups rules by `session_id` and runs
   its taint rules on `labels`. Without them, a TraceSig user had to
   convert APG exports first. With them, `tracesig scan trace.jsonl`
   works directly.
   *Design choice:* `labels` uses the **output** label (what the call
   returned), not the input label. In a taint rule the source is the call
   that brought untrusted data in (for example `web_fetch`), and the sink
   is a later call; using input labels would make the sink look like the
   source. The `untrusted` marker is added when the output's effective
   integrity set is non-empty, matching TraceSig's label vocabulary.
   *Compatibility:* both fields are derived (like `input_untrusted`) and
   ignored by `event_to_record`, so the lossless round trip still holds;
   adding fields is allowed within `schema_version` 1 by the frozen
   compatibility promise, so no version bump.
2. **R64 — CI and a contract test.** The README told contributors to run
   ruff, mypy and pytest "the same gates CI does", but the repository had
   no CI workflow, only Semgrep and publish. `ci.yml` now runs them on
   every push. The new contract test runs the real TraceSig engine over
   the committed example exports, so a change on either side that breaks
   the pairing fails CI instead of surfacing in a user's pipeline.
3. **R65 — 0.2.0.** PyPI still serves 0.1.0 (May), without anything from
   R49 onward. Bumping to 0.2.0 lets `pip install agent-policy-gateway`
   deliver the research features and the TraceSig export.

## Plain-language notes (術語白話)

- **Contract test:** a test that checks the promise between two separate
  projects (here: "an APG export can be scanned by TraceSig") by running
  both for real, so neither side can break it silently.
- **Derived field:** a value computed from other fields for convenience;
  it is recomputed, never trusted, when data is read back.

## What changed and why

1. **ROADMAP: plan revision + R66a–c.** Chinaei's *Causality
   Laundering* (arXiv:2604.04035, April 2026) shows that a refusal leaks
   information: the agent probes something protected, the "denied"
   answer itself tells it something secret (for example, that a file
   exists), and a later ordinary-looking call sends that inference out.
   APG is exposed: it records denied attempts in the call history, and
   the AgentDojo adapter and model loop show the refusal (rule id and
   reason) to the agent, but the refusal carries no taint label. R66
   splits into three daily items: (a) build a scenario family for the
   attack and measure the seven existing arms; (b) *labeled refusals*,
   where a refusal carries the label of what the refusing rule looked
   at; (c) compare three fixes (ARM's "block the next call after a
   denial", a session-wide "any prior denial" rule, and labeled
   refusals) on leak rate and benign utility. The daily task resumes
   with R66a.
2. **Paper §2 related work.** Two new paragraphs. *Content-pattern
   firewalls*: AEGIS (Yuan, Su, Zhao; USC and UC Davis; arXiv:2603.12621)
   checks each call's arguments against 22 risk patterns and JSON
   Schemas; APG decides from provenance and history instead, so the two
   catch different failures and can be stacked. *Denial feedback*: ARM,
   and why it applies to APG as built.
3. **Paper §6 limitation** "Refusals are an unlabeled channel", so the
   draft does not overclaim: none of Tables 1–4 tests this attack.
4. **Paper §7 future work** now says the TraceSig pairing shipped
   (R62–R64) and plans R66. **References** gain both papers, checked

## Plain-language notes (術語白話)

- **Causality laundering:** leaking a secret through what the agent
  *learned from being refused*, not through data it read.
- **Implicit flow / pc label:** classical information-flow term. When a
  program branches on a secret, whatever it does in either branch
  reveals something about the secret, so the result is labeled secret
  even though no secret bytes were copied. A refusal is such a branch.
- **Counterfactual edge (ARM):** a link ARM draws from a denied call to
  the next call, meaning "this call may have been influenced by that
  denial".
- **Over-approximation:** a rule that blocks everything that *might* be
  an attack, and therefore also some harmless actions (false
  positives).
